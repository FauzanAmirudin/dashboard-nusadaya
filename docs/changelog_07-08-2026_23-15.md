# Dokumentasi Perubahan Sistem - Dashboard Nusadaya
**Tanggal Pembuatan**: 7 Agustus 2026, 23:15 WIB

Dokumen ini merangkum seluruh perubahan, modifikasi fitur, dan perbaikan *bug* yang dilakukan pada sesi pengembangan kali ini. Fokus utama perbaikan mencakup sinkronisasi antar panel, penyesuaian otorisasi API, perbaikan tampilan (UI), serta penyelarasan pembacaan data dari struktur database terbaru.

---

## 1. Perbaikan Integrasi Otorisasi Panel Finance & PMB
- **Isu**: Biaya tambahan yang ditambahkan oleh tim Finance (Panel Finance) tidak muncul di Panel PMB saat admin PMB melakukan akses.
- **Akar Masalah**: *Endpoint* backend `GET /finance/student/:studentId` (`finance.ts`) sebelumnya memblokir (*forbidden*) semua _role_ kecuali "finance", "superadmin", "pa", "magang", dan "crm". Akun "pmb" tidak memiliki akses baca terhadap _endpoint_ keuangan.
- **Tindakan (Bug Fix)**: Menambahkan _role_ `"pmb"` ke dalam pengecualian (kondisi otorisasi) pada *route* backend, sehingga admin PMB sekarang memiliki hak akses (*read-only*) untuk mengambil dan menampilkan data biaya tambahan secara _real-time_.

## 2. Sinkronisasi Tampilan Tab Fee Sharing Lintas Panel
- **Isu**: Terdapat ketidakkonsistenan antarmuka tabel pada Tab Fee Sharing di Panel Finance dibandingkan dengan Panel PMB.
- **Tindakan**: 
  - Melakukan perombakan penuh pada struktur tabel `TabFeeSharing.tsx` yang berada dalam folder `panels/finance`.
  - Menyesuaikan kolom agar 100% *identik* dengan yang di Panel PMB. Urutan kolom baru menjadi: **Penerima**, **Nama**, **No. HP**, **Fee (Nominal)**, **Invoice (PDF)**, **Status**, dan **Aksi**.
  - Mengimplementasikan komponen visual yang seragam seperti *Badge* untuk Kategori, penambahan info Nomor Rekening & Bank di bawah nama utama, serta menempatkan No. HP ke kolom terpisah.

## 3. Penyesuaian Header Detail Mahasiswa
- **Isu**: Data penting seperti *Alamat Lengkap* dan *Data Orang Tua* hanya memunculkan tanda strip (`-`) pada *Header Profil* (bagian atas detail mahasiswa), meskipun data tersebut ada di database.
- **Akar Masalah**: Dampak dari restrukturisasi database sebelumnya di mana alamat dipecah menjadi banyak kolom (`addressStreet`, `addressRt`, dsb.) dan orang tua dipindah ke tabel terpisah (`student_parents`). Namun, backend API `GET /students/:id` dan komponen UI *Header* belum diperbarui.
- **Tindakan**:
  - **API Server (`core.ts`)**: Memodifikasi _query_ ORM pada *endpoint* `GET /students/:id` agar menarik data relasional dari `studentParents`. Memperbaiki proses ekstraksi *array* `Promise.all` agar _payload_ JSON dapat mengirimkan `parents`.
  - **UI/Frontend (`page.tsx`)**:
    - Membuat sistem *formatter* otomatis (`formatAddress`) untuk merangkai kembali pecahan data alamat (`addressStreet`, RT/RW, kecamatan, kabupaten, provinsi) menjadi satu kalimat alamat yang rapi.
    - Membuat sistem untuk mencari **Primary Parent** (memprioritaskan data Ayah, lalu Ibu, lalu Wali) dari _array_ tabel orang tua untuk ditampilkan pada bagian Nama Ortu, Pekerjaan, Penghasilan, dan Kontak Ortu.
    - Memperbaiki tata letak format Tujuan (Negara Tujuan & Periode) agar apabila kosong tidak memunculkan karakter rumpang `- (-)`.

## 4. Modifikasi Tabel Halaman Arsip Mahasiswa
- **Isu**: Kolom pada tabel *Master Data Arsip* mahasiswa (`archive/page.tsx`) belum mengakomodasi kolom yang dibutuhkan operasional tim.
- **Tindakan**:
  - Menghapus kolom-kolom status persetujuan yang tidak terlalu relevan (PMB, CRM, Finance, dll) dari daftar arsip.
  - Mengganti dan memetakan struktur tabel menjadi lebih tepat guna sesuai diagram yang diminta, yaitu: **Nama**, **Batch**, **Tahun Ajaran**, **Program Studi**, **Peminatan** (Sub-Program), **No. HP/WhatsApp**, dan **Aksi**.
  - Menyesuaikan *type definition* (`StudentData`) TypeScript pada *frontend* dengan menyuntikkan properti opsional baru seperti `batch`, `academicYear`, dan `subProgram` agar kompilasi bebas dari *error*.
